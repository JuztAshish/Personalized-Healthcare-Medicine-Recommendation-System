## 1. Executive Summary & Module Role

Module 3 is the **Personalized Medicine Recommendation Engine** of the Personalized Healthcare Recommendation System. It serves as the decision-support link connecting:
* **Module 1 (Data Preparation):** Reuses 11,741 cleaned medicine records and precomputed TF-IDF matrix/vectorizer artifacts.
* **Module 2 (Disease Prediction):** Receives predicted disease names generated by the machine learning classifier (`GaussianNB`).
* **Module 4 (Web Application):** Delivers personalized candidate medicines, transparent explanations, allergy screening flags, and condition warnings for rendering on the patient dashboard.

---

## 2. System Architecture & Workflow

```
[Patient / Doctor]
        │
        ▼ (Inputs Symptoms & Medical Profile)
[Module 4: Flask Web Application]
        │
        ▼ (Sends 377-dimensional binary symptom vector)
[Module 2: Machine Learning Disease Prediction] (best_model.pkl & disease_encoder.pkl)
        │
        ▼ (Outputs Predicted Disease Name, e.g. "somatization disorder")
[Module 3: Personalized Medicine Recommendation Engine]
   ├── 1. Query Normalization (parses disease name matching Module 1 vocabulary)
   ├── 2. TF-IDF Cosine Similarity Candidate Retrieval (against 11,741 records)
   ├── 3. Conservative Allergy Screening (detects patient allergens in 'composition')
   ├── 4. Preliminary Condition Precaution Scanning (scans patient conditions vs 'side_effects')
   ├── 5. Experimental Heuristic Ranking (85% Cosine Similarity + 15% Review Sentiment)
   └── 6. Explainability & Disclaimer Layer (generates match rationale and clinical notices)
        │
        ▼ (Returns Structured JSON / Dictionary)
[Module 4: Web Application Dashboard / REST API]
```

## 4. Production Service Interfaces

Module 3 provides two layers of services inside `healthcare_webapp/services/`:

### A. Core Engine: `MedicineRecommender`
*File:* `healthcare_webapp/services/medicine_recommender.py`

```python
from healthcare_webapp.services.medicine_recommender import MedicineRecommender

recommender = MedicineRecommender()

results = recommender.get_recommendations(
    disease="Asthma",
    patient_allergies=["Aspirin"],
    patient_conditions=["Hypertension"],
    top_k=5,
    filter_allergies=True
)
```

#### Parameters:
* `disease` (*str*): Predicted disease name or health condition query (e.g., `'Asthma'`).
* `patient_allergies` (*list[str]*, optional): Known active ingredient allergies (e.g., `['Amoxycillin']`).
* `patient_conditions` (*list[str]*, optional): Known pre-existing conditions (e.g., `['Vomiting']`).
* `top_k` (*int*, default `5`): Maximum number of recommendations to return.
* `filter_allergies` (*bool*, default `False`): If `True`, excludes medicines containing matching allergens. If `False`, includes them but attaches prominent `DANGER - ALLERGY MATCH` alerts.

## 6. Integration Instructions for Member 4 (Flask Web App)

Member 4 can connect the recommendation engine to `healthcare_webapp/app.py` in three simple steps without modifying any core ML models.

### Step 1: Update Imports in `healthcare_webapp/app.py`
Ensure `request` and `jsonify` are imported alongside Flask, and import the Module 3 adapter functions:
```python
from flask import Flask, render_template, request, jsonify
from healthcare_webapp.services.flask_adapter import (
    get_recommendations_for_flask,
    predict_and_recommend
)
```

### Step 2: Add Recommendation Routes
Add the following route controllers to `healthcare_webapp/app.py`:

```python
@app.route("/recommend", methods=["GET", "POST"])
def recommend_medicine():
    if request.method == "POST":
        disease = request.form.get("disease", "").strip()
        allergies = request.form.get("allergies", "").strip()
        conditions = request.form.get("conditions", "").strip()
        top_k = int(request.form.get("top_k", 5))
        filter_allergies = request.form.get("filter_allergies", "true").lower() == "true"

        results = get_recommendations_for_flask(
            disease=disease,
            allergies=allergies,
            conditions=conditions,
            top_k=top_k,
            filter_allergies=filter_allergies
        )
        return render_template("recommendations.html", data=results)
    
    return render_template("recommend_form.html")

@app.route("/api/recommend", methods=["POST"])
def api_recommend_route():
    data = request.get_json() or {}
    disease = data.get("disease", "")
    allergies = data.get("allergies", [])
    conditions = data.get("conditions", [])
    top_k = data.get("top_k", 5)
    filter_allergies = data.get("filter_allergies", True)

    results = get_recommendations_for_flask(
        disease=disease,
        allergies=allergies,
        conditions=conditions,
        top_k=top_k,
        filter_allergies=filter_allergies
    )
    return jsonify(results)
```

## 7. Clinical Safety Governance & Regulatory Policy

1. **Academic Decision-Support Prototype:** Built exclusively for research and academic evaluation.
2. **Text Similarity $\neq$ Clinical Equivalence:** Text similarity indicates keyword relevance; it does not measure pharmacological efficacy, drug bioavailability, metabolic pathways, or clinical safety.
3. **No False Safety Claims:** Candidates that pass allergen keyword checks are **never called "clinically safe"**. Absence of a keyword in a dataset does not guarantee lack of allergic reaction or excipient cross-reactivity.
4. **Side Effects $\neq$ Absolute Contraindications:** Documented side effects represent reported adverse events. Overlaps are labeled strictly as **Preliminary Warnings** advising physician review.
5. **No Dosages or Prescriptions:** The system deliberately omits dosages, frequencies, and durations.
